# 🧭 सामान्य IP/Ownership Playbook — कुठल्याही नवीन प्रोजेक्टसाठी

> **हा दस्तऐवज पोर्टेबल टेम्प्लेट आहे.** कुठलाही नवीन प्रोजेक्ट सुरू करताना
> (Claude, ChatGPT, Antigravity, Cursor, Copilot, Gemini — कुठलाही AI tool
> वापरून) या फाईलची कॉपी नवीन प्रोजेक्टच्या `docs/` मध्ये ठेवा आणि
> `[...]` जागा भरा. **हा कायदेशीर सल्ला नाही — फक्त कृती-यादी आहे.**

## 🗓️ Day-0 चेकलिस्ट — प्रोजेक्ट सुरू करतानाच (पहिल्या तासात)

कोड लिहायला सुरुवात करण्याआधीच खालील गोष्टी ठरवा — नंतर दुरुस्त करणं
कठीण आणि खर्चिक असतं (हे याच प्रोजेक्टमध्ये अनुभवलं — git history
सुरुवातीपासून चुकीच्या नावावर गेली होती).

- [ ] **कायदेशीर मालक कोण?** — व्यक्ती (तुमचं Aadhaar/PAN वरचं नाव) की
      कंपनी (नोंदणीकृत entity)? हे सुरुवातीलाच ठरवा — नंतर बदलणं
      = सर्व कागदपत्रं + git config पुन्हा करावे लागतात.
- [ ] **Git identity सुरुवातीलाच बरोबर सेट करा:**
  ```bash
  git config user.name "खरं नाव / कंपनीचं नाव"
  git config user.email "अधिकृत ईमेल"
  ```
  ⚠️ AI coding tools (Claude Code, Antigravity, Cursor इ.) कधीकधी स्वतःचं
  डीफॉल्ट identity (उदा. "AI Agent", "Claude", tool-specific email) सेट
  करतात — **पहिल्याच commit आधी** `git config` तपासा.
- [ ] **Repository सुरुवातीपासून PRIVATE ठेवा** (GitHub/GitLab/Bitbucket) —
      नंतर public करायचं ठरलं तर उघडता येईल, पण सुरुवातीपासून private
      असणं सर्वात सोपं संरक्षण आहे.
- [ ] **LICENSE file पहिल्याच commit मध्ये टाका** (रिकामी repo सुद्धा
      "no license = no rights granted" या डीफॉल्टवर चालते, पण स्पष्ट
      असणं केव्हाही चांगलं).
- [ ] **कोणतं नाव/ब्रँड वापरणार आहात ते आधीच सर्च करा** — Google +
      संबंधित देशाचं Trademark database (भारतासाठी ipindia.gov.in) —
      आधीच कोणी तेच नाव वापरत नाही ना.

## 📚 4-स्तरीय संरक्षण मॉडेल (कुठल्याही प्रोजेक्टला लागू)

```
स्तर 1: कायदेशीर दस्तऐवज  → LICENSE, NOTICE, OWNERSHIP.md
स्तर 2: तांत्रिक पुरावा   → Private repo, अखंड git history, backup
स्तर 3: क्रिप्टोग्राफिक   → Signed commits, timestamping (OpenTimestamps)
स्तर 4: सरकारी नोंदणी    → Copyright, Trademark (देशानुसार)
```

### स्तर 1 — कायदेशीर दस्तऐवज (मोफत, आजच करा)

| फाईल | उद्देश | टेम्प्लेट कुठे |
|------|--------|----------------|
| `LICENSE` | कोण वापरू शकतं, कोण नाही | या प्रोजेक्टमधील `LICENSE` फाईल base म्हणून वापरा |
| `NOTICE` | सार्वजनिक मालकी घोषणा | `NOTICE` फाईल base म्हणून वापरा |
| `OWNERSHIP.md` | कोण, कधी, कसं बनवलं — प्रामाणिक नोंद | `OWNERSHIP.md` base म्हणून वापरा |

**नियम:** या फाईल्समध्ये **कधीही अंदाजाने/कल्पनेने नाव किंवा आकडा लिहू
नका.** मालकाचं नाव माहीत नसेल तर `[नाव भरणे बाकी]` असं ठेवा — चुकीचं
नाव लिहिण्यापेक्षा रिकामी जागा हजारपट सुरक्षित (हे या प्रोजेक्टमध्ये
प्रत्यक्ष घडलेली चूक होती — Windows username वरून आडनाव अंदाजलं गेलं
आणि कायदेशीर कागदपत्रात गेलं).

### स्तर 2 — तांत्रिक पुरावा (मोफत)

- [ ] Repository private ठेवा (गरज असेल तेव्हाच public करा — जाणीवपूर्वक)
- [ ] **जुना git history कधीही rewrite करू नका** (`rebase -i`,
      `filter-repo`, force-push) — अखंड hash-chain हाच सर्वात मजबूत
      "हे केव्हा घडलं" चा पुरावा आहे. नाव चुकलं असेल तर **`.mailmap`**
      वापरा (इतिहास न बदलता जुन्या commits चं display-नाव बदलतं):
      ```
      # .mailmap
      खरं नाव <खरा-email> जुनं-नाव <जुना-email>
      ```
- [ ] नियमित **git bundle backup** घ्या (महिन्यातून एकदा पुरेसं):
  ```bash
  git bundle create backup-$(date +%Y%m%d).bundle --all
  ```
  दोन वेगळ्या ठिकाणी ठेवा (email-to-self + encrypted cloud/USB).
- [ ] GitHub/GitLab खात्यावर **2FA चालू** करा.
- [ ] Collaborators/access list वेळोवेळी तपासा.

### स्तर 3 — क्रिप्टोग्राफिक पुरावा (मोफत, 15 मिनिटं)

- [ ] Commit signing चालू करा (SSH सोपं आहे):
  ```bash
  git config --global gpg.format ssh
  git config --global user.signingkey ~/.ssh/id_ed25519.pub
  git config --global commit.gpgsign true
  ```
  Public key GitHub/GitLab सेटिंग्जमध्ये upload करा (नाहीतर "Verified"
  बॅज दिसत नाही).
- [ ] मोठ्या milestones ला (major release, funding round आधी वगैरे)
      **OpenTimestamps** ने current commit hash stamp करा —
      https://opentimestamps.org (मोफत, blockchain-backed).

### स्तर 4 — सरकारी नोंदणी (सशुल्क, गरजेनुसार)

भारतासाठी (इतर देशांसाठी समकक्ष agency शोधा):

| कृती | कुठे | कधी करावं |
|------|------|-----------|
| Copyright नोंदणी (Form XIV) | copyright.gov.in | Product स्थिर झाल्यावर, विशेषतः निधी/विक्री आधी |
| Trademark शोध + अर्ज (TM-A) | ipindia.gov.in | नाव/ब्रँड नक्की झाल्यावर, launch च्या आधी |
| कंपनी नोंदणी (Pvt Ltd/LLP) | mca.gov.in | Revenue/liability सुरू होण्याआधी |

⚠️ **या पायरीसाठी नेहमी IP वकिलाचा सल्ला घ्या** — फी, timeline, आणि
published/unpublished सारखे declarations चुकले तर अर्ज नाकारला जातो
किंवा उलट परिणाम होतो.

## 🤖 AI-प्लॅटफॉर्म-विशिष्ट खबरदारी (हे नेहमीच्या IP गाईडमध्ये नसतं)

### 1. कोणत्या AI ला काय दाखवताय याचं भान ठेवा
- Enterprise/paid-tier AI tools (Claude API/Console with data-retention
  off, ChatGPT Enterprise, इ.) सहसा तुमचा input training साठी वापरत
  नाहीत — पण **मोफत/consumer tier** मध्ये हे धोरण वेगळं असू शकतं.
- प्रत्येक नवीन AI tool वापरण्याआधी त्याचं **Terms of Service मधील
  data-usage/training clause** एकदा वाचा — विशेषतः proprietary/
  confidential कोडसाठी.

### 2. Output ownership (कोणाचं आहे हे output?)
- बहुतांश प्रमुख AI प्लॅटफॉर्म्स (Anthropic, OpenAI, Google) त्यांच्या
  ToS मध्ये **तुम्हाला दिलेल्या output वरचे हक्क तुम्हाला** देतात —
  पण हे प्रत्येक प्लॅटफॉर्मचं धोरण वेगळं असू शकतं, त्यामुळे प्रत्येक
  वेळी गृहीत न धरता **त्या-त्या प्लॅटफॉर्मच्या चालू ToS मध्ये तपासा.**
- हे तुम्हाला output वापरण्याचा हक्क देतं — पण **AI ने अंतर्भूत केलेला
  तिसऱ्या पक्षाचा कॉपीराइटेड कोड** (जर मॉडेलने चुकून जसाच्या तसा कॉपी
  केला) याची जबाबदारी अजूनही गुंतागुंतीची legal क्षेत्र आहे — मोठ्या
  प्रमाणावर वापरण्याआधी (commercial product) कोड review करा.

### 3. Multiple AI agents/sessions एकाच repo वर काम करत असतील तर
- (हे या प्रोजेक्टमध्ये प्रत्यक्ष घडलं — Claude आणि दुसरं AI tool दोन्ही
  एकाच repo वर काम करत होते.)
- प्रत्येक tool च्या commits ओळखण्यासाठी **वेगळे git author अनिवार्य नाही,
  पण commit message मध्ये कोणत्या session/tool ने काम केलं याची नोंद
  उपयुक्त** ठरते — भविष्यात "कोणी काय केलं" शोधताना मदत होते.
- सर्व AI-tool commits **तुमच्याच** GitHub खात्यातून push व्हाव्यात —
  वेगवेगळ्या AI tools साठी वेगवेगळे GitHub खाते वापरू नका (मालकी
  विखुरते).

### 4. Prompt/context मध्ये तिसऱ्या पक्षाचा गोपनीय डेटा टाकू नका
- क्लायंटचा डेटा, दुसऱ्या कंपनीचा सोर्स कोड, वैयक्तिक ओळखीचा डेटा —
  हे कुठल्याही बाह्य AI मध्ये पेस्ट करण्याआधी करार/privacy दायित्व तपासा.

## 🚨 आपत्कालीन प्रतिसाद (कोणी कोड चोरला/खोटा दावा केला तर)

1. पुरावे गोळा करा (screenshots + तारीख, तुमची git history, OTS proofs)
2. Platform च्या takedown प्रक्रियेतून तक्रार करा (उदा. GitHub DMCA:
   github.com/contact/dmca)
3. वकिलामार्फत cease & desist नोटीस
4. गंभीर असल्यास सायबर क्राईम पोर्टलवर तक्रार (भारत: cybercrime.gov.in)
5. दिवाणी/फौजदारी कारवाई — वकिलाच्या सल्ल्याने, संबंधित देशाच्या
   copyright कायद्याखाली

## ⚠️ या प्रोजेक्टमधून शिकलेले धडे (Anti-patterns — टाळा)

1. **नाव अंदाजाने भरू नका.** Username/email वरून खरं नाव कधीही अंदाजू
   नका — रिकामी जागा ठेवा, विचारा, मगच भरा.
2. **कायदेशीर आकडे (दंड, फी, timeline) न तपासता लिहू नका.** प्रत्येक
   देश/कायद्याचे नेमके आकडे अधिकृत स्रोतावर तपासा — अंदाजे/round
   figures टाकू नका.
3. **Git history rewrite करून "साफ" करण्याचा मोह टाळा** — जुनी, "चुकीची"
   दिसणारी history हाच सर्वात मजबूत पुरावा असतो.
4. **"XX% सुरक्षित" सारखे निराधार आकडे वापरू नका** — एकतर पडताळणीयोग्य
   तथ्य सांगा, नाहीतर गुणात्मक विधान करा ("मजबूत", "अपुरे").
5. **मॉडेल/session बदलल्यावर मागचं उत्तर एकदा तपासा** — वेगळा मॉडेल
   (उदा. वेगवान/स्वस्त मॉडेल) आधीच्या सत्याधारित उत्तराला confidently
   चुकीच्या तपशीलांनी बदलू शकतो. संवेदनशील (कायदेशीर, आर्थिक) आउटपुट
   नेहमी एकदा cross-check करा.

नवीन प्रोजेक्ट सुरू करताना:
```bash
# 1. ही फाईल नवीन प्रोजेक्टमध्ये कॉपी करा
cp TEMPLATE_IP_OWNERSHIP_PLAYBOOK_MARATHI.md /path/to/new-project/docs/

# 2. Day-0 चेकलिस्ट सुरुवातीलाच पूर्ण करा (git config आधीच)

#    प्रोजेक्ट-विशिष्ट माहितीने भरा
```
